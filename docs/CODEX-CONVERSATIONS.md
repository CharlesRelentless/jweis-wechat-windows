# Jweis 读取和接续 Codex 对话

微信桥接的职责是将本人来信交给原 Jweis，并将其回答发回微信。检索或继续已有 Codex 对话需要原 Jweis 的原生对话工具真实可用；读取本地笔记、另一助手转述、TLS 探测或 API accepted 均不等于这个能力已经接通。

## 先区分失败位置

| 现象或错误 | 应核对的层次 | 不能直接推出的结论 |
| --- | --- | --- |
| 电脑显示在线，但 durable WebSocket 初始化超时 | 该版本桌面应用的云端连接是否使用适用的代理，认证握手是否完成 | 不能仅凭电脑在线、模型可用或系统代理开启认定连接正常 |
| 通用目录元数据加载警告 | 对齐调用时间、host 和实际原生读写结果 | 此警告可能与成功操作同时出现，不能单独认定根因 |
| `AbsolutePathBuf deserialized without a base path` | 任务路径及原生请求参数处理 | 这是另一类尚未解决的问题，不能声称部署中继会修复它 |
| 微信 MCP 插件连接失败、状态请求超时 | 插件目标、隧道请求排队/分发、桥接及真实认证调用 | 中继 ready 或微信轮询新鲜不能证明插件可用 |

本仓库另外收录了可选的 [Windows 固定目标中继](../windows/codex-durable-relay/README.md)。它用于经核验的 durable 连接代理路径缺失：将固定云端域名的 TLS 字节通过已有本机 HTTP CONNECT 代理转发。它不会解密 TLS、创建模型、重放消息或替换原 Jweis。

## 可复用的排查与恢复顺序

1. 从当前错误和原生调用时间定位失败层，区分 local 读取、durable 连接和 Dot 发起调用。只看必要的脱敏事件，不公开完整桌面日志或对话正文。
2. 对固定目标做无凭据的直连/已有代理 TCP、TLS 对照。对照支持网络假设，不能证明经过认证的 WebSocket 或对话操作成功。
3. 核对当前 Codex 版本及连接实现。只有证据支持适用的代理路径缺失时才考虑该中继；更新 Codex 后重新核验，不能依赖旧结论。
4. 审阅中继的 [来源和修正](../windows/codex-durable-relay/docs/PATCHES.md)、[安全边界](../windows/codex-durable-relay/SECURITY.md) 与 [运维及清理](../windows/codex-durable-relay/docs/OPERATIONS.md)，先构建、隔离测试和安装预览。
5. 需要实际安装时取得当前主机和系统修改的明确授权。安装涉及一个整机 hosts 域名映射、受保护目录、两个计划任务及生命周期服务；其他使用系统解析访问相同域名的程序也会受到影响。源码发布或历史授权不构成新的安装许可。
6. 安装失败先核验清理状态，不覆盖重试、不盲删目录、不用旧 hosts 全文件覆盖并发修改。清理入口和限制见组件运维说明。

## 必须完成的原生验收

- 由原 Jweis 发起原生读取，核对本人已授权目标对话的真实正文；本聊天本地读取成功不能替代 Dot 发起的读取。
- 只有本人指定或明确授权目标与内容后，才向已有 Codex 对话发送一次接续消息。核对目标实际收到、回复完成，以及原 Jweis 再读回同一结果。只提交成功不算完成。
- 对齐本地桥接事件的调用时间、host 和成功状态，并与原对话独立核对；标识和原文保留私有。
- 如果请求来自微信，还需核对原 Jweis 的回复状态与本人手机收件次数。不能从原生任务成功推断微信收件成功。
- 单次停启恢复、隔离 CI 与历史验收不能证明长期无人值守稳定，休眠、注销和实际覆盖缺口应分别记录。

2026-10-25 的私有本机记录曾通过 Dot 原生读、接续、目标回复读回和一次真实停启；本仓库公开其实现与可复用方法，保留证据边界，不发布原始对话、账号、调用标识、运行配置或日志。当前路径解析错误及微信插件超时仍需单独完成验收。
