# 每周维护约定

本项目每周检查固定上游和官方连接组件的变化；运行在原生 Codex 自动化中，不在仓库添加第二套调度器。GitHub Actions 只执行离线验证。

每次维护先确认仓库、工作区状态和 AGENTS.md，检查上游提交、官方发布说明及有证据的兼容问题。没有相关变化时不制造提交，不重复通知。

可选 `windows/codex-durable-relay` 的固定来源记录于其 `UPSTREAM-BASE.json`。维护同时核对上游差异和本地恢复补丁，修改该组件后用 Windows PowerShell 5.1 执行其 `scripts/Test.ps1` 与 `scripts/Check-PublicFiles.ps1`，保留 Node 22/24 CI。先区分 durable 网络连接、原生路径参数和微信插件故障；不能将一个分支的修复推广到另一个分支。安装、升级已有中继、hosts/任务/服务变更和跨对话发送仍需对应的当前授权，不由每周源码维护自动执行。

有实际需要的改动放在隔离候选目录或分支，保留运行目录和私有状态。修改后执行完整 unit tests、schema 检查，以及受影响的 Windows / 安全边界验证。通过后提交带有问题、行为和测试证据的可审阅更新；涉及公共接口、迁移策略或权限范围的改动应另行确认。

维护只更新源码和文档，不自动重启真实桥接、不重新批准 OAuth、不读取凭据或私人消息、不改本机全局配置。发布新的发行版或部署需要对应授权和真实验收。可以创建审阅 PR，不能以离线 CI 推断手机或产品端通过。

每次候选提交前检查 Git diff、待提交文件与历史，排除 runtime、日志、数据库、二维码、账号标识、私人 callback、真实配置和第三方二进制。保留上游 MIT 与第三方 notice。

临时 HTTPS 地址、内存 OAuth 与前台 Job 的限制必须继续公开记录。修复或文档说明不能抹去失败的无人值守验收；只有新的实测证据可以更新验证结论。
